# 要件定義

## 1. 概要

本プロジェクトは、個人向け日報・作業記録Webアプリケーションである。

ユーザーが日々の作業内容をMarkdown形式で記録し、過去の日報を作成・閲覧・編集・削除できることを目的とする。

MVPではNext.js + TypeScriptによるフルスタック構成を採用する（詳細は [architecture.md](./architecture.md)）。

**MVPの完成を最優先し、過剰な抽象化や過剰設計を避けること。**

---

## 2. MVP Scope

### 必須機能

| 区分 | 機能 |
|---|---|
| 認証 | ユーザー登録 |
| 認証 | ログイン |
| 認証 | ログアウト |
| 日報 | 日報作成 |
| 日報 | 日報一覧表示 |
| 日報 | 日報詳細表示 |
| 日報 | 日報編集 |
| 日報 | 日報削除 |
| 日報 | Markdown入力・プレビュー |

各機能の操作の流れは [use-cases.md](./use-cases.md) を参照。

### 対象外（MVPでは実装しない）

- タグ管理・タグ検索
- ゴミ箱・復元
- チーム・組織管理
- 管理者専用画面
- ロールベースの権限管理
- メール通知
- 日報の自動保存
- 下書き保存
- 画像アップロード

対象外機能について、明示的な指示なしに実装を追加しないこと。

---

## 3. 業務ルール

### 日報

- タイトルは必須、最大200文字
- 本文は必須、最大20,000文字
- 本文はMarkdownとし、プレーンテキストとして保存する
- 同一日に複数の日報を作成可能
- 日報の日付は時刻を含まない

### 権限

MVPでは個人ユーザーのみを対象とするため、複雑なRBACは導入しない。

- 認証が必要な画面へ未ログインでアクセスできない。
- ユーザーは自分の日報のみ閲覧・編集・削除できる。
- 他ユーザーの日報は存在を秘匿する（存在しない日報と同じ扱いにする）。

---

## 4. 非機能要件

- 認証・認可・入力値検証はサーバー側で行う。
- Markdown表示時はXSS対策を行う。
- 保存中の二重送信を防止する。
- エラーメッセージをユーザーに分かりやすく表示する。
